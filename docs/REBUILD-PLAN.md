# 以播放链路为中心的重构：第二轮调研与实施计划

更新：2026-11-19。状态：**本轮线下实现与验收完成，未部署。** 最新结果见 `OFFLINE-ACCEPTANCE.md`；下文保留调研、取舍与分阶段实施记录，早期“待实施”描述不代表当前状态。

## 1. 纠正目标

前一轮完成的是声明拆分、构建和旧行为回归，不等于产品重构。公开的 14273 静态页面只用于看原版外观，没有完整 API，不应被当成新版本。

用户要求：先学习多个项目，再取长补短；核心反代最重要，要好用、稳定、快；界面保留个人版毛玻璃与真实背景壁纸的方向，但不止照搬旧页面；增加有实际价值的功能，减少低价值复杂度。

个人版与多人版仍是两个发行版。公共代理内核共享，身份、路由归属、配额和数据库适配独立；不因共享内核把两版强行合并。现有数据、备份与源码不删除，Cloudflare 写操作另行确认。

补充规范核对：

- [Cloudflare Streams](https://developers.cloudflare.com/workers/runtime-apis/streams/)：原样返回上游 body 已是合适流式路径，不为“优化”无条件加 tee、读完整 body 或 drain。
- [NGINX proxy](https://nginx.org/en/docs/http/ngx_http_proxy_module.html)：区分请求缓冲和响应缓冲；非幂等请求不能随意重放；响应已发给客户端后无法切换上游拼接补救；读超时与整个播放时长不是一回事。
- [Caddy reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)：重试次数与总时间预算分开；健康检查不等于真实播放成功；低延迟参数可能改变断连取消行为，不能见到“低延迟”就照开。Worker 无法直接照搬 Go transport 的 TCP/TLS 选项。

仅参考设计自行实现；复制第三方源码前单独核验许可证、归属和许可兼容性。

## 3. 已在当前源码发现的具体问题

1. `src/editions/{personal,multi}/proxy/pipeline.js` 对所有非 GET/HEAD 请求调用 `request.arrayBuffer()`，缺少字节上限。个人版 WebSocket 中继辅助函数也存在 clone 后全读逻辑。
2. 当前 `classifyRequest()` 只凭有限后缀识别主流；`/Audio/id/stream`、`/Videos/id/stream` 等无后缀媒体可能落入 `other`，误受普通请求限流和中继“image”策略影响。`.ts` 整流与 HLS 分片也未清晰区分。
3. 失败切换分支保留 `fallbackResponse`，替换和成功返回时需明确取消弃用响应；请求的下游取消信号没有统一传入各条 fetch 路径。具体传播需在 workerd 实跑，不能只看 Node mock。
4. 个人版图片缓存键会删除部分鉴权查询参数，但拒绝缓存的条件只查 header；必须验证 query token 与权限隔离，不以“命中率高”为理由共享私有图片。
5. 熔断状态按 host 存储，可能使不同路由/用户互相影响。需要改为明确的路由、所有者、上游身份，并限制内存表大小。
6. 原生流保持了低开销，但现有 42 项测试没有证明真实吞吐和首帧时间；公开静态展示也无法测试任何实际代理行为。
7. 预览用 SVG 占位而非照片，背景对比又低，不能代表用户要求的壁纸效果。修复应与数据面代码分开，不能为了获取壁纸打开整个预览的外网访问。

## 4. 功能取舍（计划，不是已交付功能）

### P0：先保证正确与稳定

- 明确整流、分片、播放列表、音频、字幕、图片、API、WebSocket 分类。
- Range / If-Range / HEAD / 206 / 416 逐跳保真；不伪造长度、范围或成功状态。
- 统一 URL 构造与重定向策略，保留签名原始查询拼写、重复键、编码和前缀；逐跳鉴权剥离与目标校验。
- 弃用响应释放；客户端取消停止上游；已开始返回的流不重试。
- 有界请求体与 JSON 改写；可重放不代表允许重试，非幂等请求默认不重放；超限或未知长度优先流式。
- 缓存隔离、熔断隔离、限流边界测试；开发依赖漏洞评估。

### P1：新增直接服务于播放与日常管理的能力

- **路由诊断**：显示命中的策略、是否直连/Worker/VPS、上游响应头耗时、重定向跳数、Range 支持和失败阶段；输出脱敏，不暴露真实 token、媒体路径、内网地址。
- **有界故障切换**：有限次数与总预算、按路由隔离的健康状态、半开恢复；同一播放会话尽量保持同源，不能在不同文件之间盲切。
- **安全直链缓存**：仅显式允许的链路；身份/租户/UA 隔离；不过签名有效期；并发去重只共享解析结果，绝不共享不同 Range 的响应 body。初始默认关闭，验证后启用。
- **路由操作**：搜索/分组、复制线路、批量启停、导入校验和差异预览；修改可撤销，不用手改大 JSON。
- **故障记录**：脱敏 request ID、原因、策略与耗时；采样且异步，不能每段视频写一次 D1。

### P2：界面与可维护性

- 以原个人版的壁纸、毛玻璃、主题切换为视觉基础，重新组织“线路 / 诊断 / 活动 / 设置”，不是复制别人面板，也不是照搬旧信息架构。
- 壁纸正常显示；可调遮罩、加载失败回退纯色；展示环境使用本地缓存的真实壁纸，避免照片源慢拖住管理页。
- 常用项前置；兼容头、映射规则、DNS、Telegram/日报等收进高级/集成区，不占主工作流。
- 个人版不出现用户邀请等控件；多人版保留严格服务端权限。

### 不新增 / 候选弱化（不静默删除已有能力）

- 不加无法控制 Worker transport 的假 H2/H3 加速开关，不虚构测速、活跃人数或“已加速”数值。
- 不做整片视频预取、无界统计 tee、自动 HTTPS 降级、任意地址 raw 转发、跨用户私有 API 缓存。
- DNS 操作、日报和复杂规则先移至高级区；是否最终移除，依据依赖和使用价值再确认。导入旧配置继续兼容。

## 5. 内核边界

```text
request → edition auth/route resolver → shared proxy context
        → classify → explicit policy → upstream plan
        → bounded fetch/failover → redirect decision
        → response headers → native stream / bounded metadata rewrite
        → sampled redacted diagnostics (off hot path)
```

Edition 适配器负责用户归属、数据库与中继协议差异；共享层不能读取另一用户配置。媒体成功路径不解析 JSON、不读完整 body、不等诊断数据库写入。高级管理功能不进入主字节流路径。

## 6. 验收方式：可证伪，不喊“更快”

1. 固定原始 Worker 基线、配置和生成数据，保留原 42 项测试。
2. 新增针对上述缺陷的失败用例，再改内核：未知长度上传、取消、慢客户端、连接中断、循环跳转、跨身份缓存、非幂等请求、不规则签名 URL。
3. workerd + 可控本地上游验证真实 HTTP：首字节、持续吞吐、慢读、取消、内存增长、请求次数；1/8/32 并发，冷/热、直连/中继分别报告。资源不足时标明未跑，不伪造。
4. 同机同链路 A/B 报告 p50/p95、吞吐、RSS 与失败率，不把服务器响应头时间说成播放器首帧；在协议正确和资源有界前提下比较。
5. 客户端矩阵：Emby Web、至少一个桌面/手机常用播放器，覆盖起播、快进拖动、字幕、长播、HLS；真实测试需要用户授权与测试地址，绝不从现有生产配置偷取。
6. 完成核心之后再交付可交互页面，展示域与生产隔离；正式发布需配置迁移/回滚说明并单独确认。

阶段交付必须逐条标注“已实现 / 已测 / 未验证”，不能用模块数、打包大小或截图代替可用性证明。

## 8. 第一阶段内核重做（用户确认重新推进后）

本地分支：`refactor/playback-first`。开始前的 tracked diff 与额外文件快照存放在工作目录 `rebuild-checkpoints/`，原交接归档与 `.git` 历史保留。不把既有修改丢弃重置。

### 已实现

- `body-plan.js`：只对声明长度不超过 256 KiB 的请求体做有界读取；未知长度/大请求保持一次性流式上传；谎报小长度超限后重放已读前缀并继续流式，不截断、不 clone/tee 全量请求。
- `lifecycle.js`：上游请求携带客户端取消信号；只允许 GET/HEAD 参与自动故障重试；取消弃用响应不等待可能挂起的 cancel promise。
- `cache-policy.js`：含 token/signature/ApiKey 查询、Cookie 或认证头的图片/静态请求不读写共享缓存；不覆盖源站 private/no-store/no-cache/Set-Cookie/Vary 策略。
- `redirects.js`：共享逐跳状态机，最多跟随 5 跳；循环检测；每跳校验协议、userinfo、字面私网地址及 HTTPS 降级；跨域后不恢复原客户端凭据；保留签名 URL 与 Range/If-Range；303 与 POST 301/302 正确转 GET；不能重放的上传不跟随保留方法的跳转。
- `circuit.js`：按入口 host、所有者、路由、上游 origin 隔离故障状态；清理过期记录且最多 512 条，不再把同一 host 上其他用户线路一起标坏。
- 两版 pipeline 接入上述模块；保留原生媒体响应 body、不加入计速 tee。故障审计使用 waitUntil，不再等待 D1 写入；日志不带原始媒体路径/原始上游错误 URL。公共 502 不回显上游异常详情。

### 已验证

- 保留原 42 项基线/协议用例；补充分类、上传/取消/缓存、重定向、故障隔离测试。
- 真实 workerd（Miniflare）验证两版的 Range、HEAD、已知长度、签名跳转、跨域剥离认证、上传、媒体结束前分块返回。上游全部为可控合成响应，不连接生产。
- 这份 runtime 流式检查使用 128 KiB 初始块来避开本地 Miniflare 桥接小块聚合，不是首字节性能基准，也不证明真实 CF 网络同样的分块行为。
- 首轮完整 `npm run check`：88/88 自动测试、8/8 浏览器通过；后续若改动，以最新执行日志为准。

### 明确的兼容性变化

- 关闭写请求的隐式故障重放，避免重复提交。客户端看到失败后是否手动重试由客户端决定；不再以“内存里有一份 body”作为自动重试理由。
- 非显式直连的重定向链不允许 HTTPS 降至 HTTP；确需 HTTP 的源站应直接显式配置并评估安全边界。
- 未知长度流式上传遇到 307/308 不能安全重放时返回 502；不偷偷缓存整包以伪装兼容。
- 含鉴权的图片不再共享缓存，命中率可能下降，先保证不越权。仍未证明业务允许对这些图片做任何跨用户去鉴权缓存。

### 尚未完成，不能视为全项目交付

- 完整的上游请求次数/总时间预算、故障半开恢复与播放会话黏性。
- 有界 PlaybackInfo 改写（多人版目前仍有 clone().json()），直链解析缓存与安全 single-flight。
- 以上目标检查主要防止 URL 字面绕过；不是通用 DNS 重绑定防护的证明，不能把不可信任意源站变成开放代理。
- WebSocket 专用路径的完整凭据/取消/中继兼容矩阵。
- 路由诊断 API/UI、批量配置体验、壁纸/页面重做、依赖漏洞修复。
- 真实 HTTP 慢客户端/中断压测、吞吐/RSS 基线 A/B、真实播放器首帧与拖动验收。
