## 1. 哪些是真正改动，而不是换皮

| 部分 | 本轮交付 |
| --- | --- |
| 代理内核 | 两版接入共享请求体策略、生命周期、缓存规则、时间/次数预算、逐跳重定向、故障隔离模块；不是把原函数简单拆文件 |
| 上传与内存 | 显式小请求最多缓冲 256 KiB、读取最多 5 秒；未知长度/大上传一次性流式传递；谎报小长度超限时保留前缀继续流式，不截断 |
| 播放链路 | Range/If-Range/HEAD/206/416 保真；音频、无后缀整流、下载、分片/播放列表单独分类；原生媒体响应不加 tee/drain，不整片预取 |
| 重试与恢复 | 自动故障切换仅 GET/HEAD，最多 3 个主目标、一次链路最多 9 次出站；响应头单次 10 秒、合计 20 秒预算，拿到响应头就清除该计时器，不因电影播放长而截流；故障状态按用户/路由隔离，512 条硬上限，半开探测租约防止同时回切 |
| 取消与资源释放 | 客户端退出/拖动取消传播至上游，弃用响应释放；已发出的媒体流不在内部拼接另一个源站；真实回环 HTTP 取消已验证 |
| 重定向 | 每跳手动检查，最多 5 跳；保留签名 URL 编码/重复参数，跨域后不恢复客户端凭据；阻止私网字面地址、URL 用户名密码、HTTPS 降级、非法协议和循环；303 与 POST 301/302 转 GET；不可重放上传的 307/308 明确失败 |
| 缓存与元数据 | 认证头/Cookie/ApiKey/token/signature 请求不进共享缓存；尊重源站 private/no-store/no-cache/Set-Cookie/Vary；PlaybackInfo 最多 1 MiB、5 秒、4 个并发读者，超限/繁忙时不无限排队或复制整包 |
| WebSocket | 升级请求也执行 IP、自定义头、后台 Cookie 清理和跨域推流凭据策略；真实 workerd echo/close 通过 |
| 隐私与协议 | 后台会话不转给源站；逐跳头和 Connection 点名字段清理；保留独立 Set-Cookie、长度与范围验证头；后台审计异步且不记录媒体路径和上游异常 URL |
| 进度上报 | 按入口/路由/设备隔离；无法识别设备/会话时不再把同一 NAT 的不同观众一起吞掉进度 |
| 访问边界 | 任意原始 URL 代理默认关闭；必须显式 `DISABLE_DIRECT_PROXY=0` 且配置 `DIRECT_PROXY_ALLOW` 才启用。普通使用只需登记线路，不开放公共转发代理 |

### 新的日常管理能力

- **链路诊断**：管理员显式发起，只对已登记的最多 3 个源站做 HEAD 检查，显示状态、响应头耗时、跳转次数、Range 声明和实际策略。结果不回显源站 URL、路径、密钥；不冒充首帧、RTT 或播放速度。
- **复制为新线路**：保留设置、生成不冲突路径，清空原记录标识，先打开表单，保存前不写入。
- **批量启停与状态筛选**：显式选择/确认，失败时报告完成数量，不假装跨请求事务成功。普通用户不获得管理员批量操作权限。
- **配置导入只读预检**：显示新增/覆盖数量、拒绝无效/重复线路及非法推流目标；不回显配置密钥；取消不改数据库。前端限制 2 MiB，服务端 JSON 同样有实际字节/时间上限。
- **轻量工作台**：真实配置数量、线路主工作流、主题持久化、移动布局；不增加假吞吐、虚拟“已加速”或无法控制的 H2/H3 开关。

## 3. 本轮明确不加入的东西

这不是把所有参考项目的功能堆起来：

- 不增加全量视频预取、无界后台测速、媒体 tee 计速或私有 API 共享缓存。
- 不引入直链解析结果缓存/持久预热与跨用户 single-flight：当前没有足够的真实签名寿命、UA 绑定和授权样本来证明收益与隔离，继续保留原生直链/透传策略。该项为本轮明确舍弃，不宣称已实现。
- 不做随机分流或在两个可能不是同一文件的源站间拼流；仍按配置主备顺序工作。故障恢复后是否适合真实播放器会话，需要真实客户端验收，不能用“自动更快”包装。
- 不新增商业化/订阅/复杂配额功能，不强行合并个人版与多人版。多人版既有用户、邀请、配额和子域名边界继续保留。

### 性能数据的正确解释

原始结果为 **`docs/BENCHMARK-RESULTS.json`**，可用 `npm run bench` 复现。脚本使用真实回环 HTTP + workerd 管线 + 合成 HTTP 源站，每个请求 2 MiB，3 轮，1/8/32 并发，每组 3/24/96 个样本；两版顺序相反，减少固定顺序偏差。不是公网测试，也不是播放器首帧。

最近一次 32 并发的观察：

| 发行版 | 原版聚合 MiB/s | 重构 MiB/s | 原版首字节 p95 ms | 重构 p95 ms |
| --- | ---: | ---: | ---: | ---: |
| 个人版 | 377.38 | 463.37 | 150.97 | 130.48 |
| 多人版 | 491.02 | 484.35 | 114.36 | 113.14 |

这是单次本地测量，个人版观察到改善，**多人版没有证明更快**；复跑过程中其 p95 也曾增加。不能据此宣传固定加速比例；执行顺序、JIT、GC、宿主机负载和样本量会影响结果。Node RSS 包含测试驱动与源站，不能拿其增长当作 Worker 的内存回归；workerd RSS 单独记录，亦不是长期生产内存上界证明。

核心成功路径仍保持原生流，改进的确定收益是资源有界、取消和故障行为更明确。真实速度需同网同源同客户端 A/B，而不是把本地吞吐写成用户网速。

## 6. 兼容性变化、上线门槛与回滚

1. 仍使用原 D1 `SCHEMA_ID`：个人版 `proxy-v6.4.8`、多人版 `multi-v6.8.5`，**未增加数据库迁移**。布局、诊断、预检没有新表。
2. 写请求不自动故障重放；原始地址代理默认关闭；HTTPS 不自动降级；含鉴权的资源不共享缓存。这些是有意收紧，不是对旧行为完全无差别。
3. HTTP 307/308 如果需要重放未知长度大上传，返回明确 502，而不是暗中缓存整包；metadata 过大/编码不适合/并发繁忙时保持原始响应，超时则 502。需要这些边缘场景的用户应先用实际客户端验收。
4. 字面地址检查不是完整 DNS 重绑定防护，管理员配置的源站必须可信；两版数据库、域名与权限绑定必须分开。
5. 尚未验证真实 Emby/Jellyfin、真实 VPS 中继、网盘签名寿命、真实播放首帧/长播/字幕、生产 WebSocket/Cloudflare Analytics；它们是**上线前验收门槛**，不是本次合成检查已通过的内容。本次未获取或使用生产凭据。
6. 任何上线必须另行确认：核对 Worker/DB/变量/域名绑定，备份数据库，保留原版本回滚，先个人版灰度，再单独评估多人版；不在本轮执行这些写操作。
7. 恢复代码时将最初交接包解到**新目录**对照，不用 `git reset --hard` 丢弃工作区。原交接归档和 `rebuild-checkpoints/` 在工作目录上级保留。
