# 个人版部署教程：Cloudflare Workers + D1

更新：2026-11-25；适用 `v6.4.9-refactor.8`。依据作者提供的《个人版部署教程》整理，保留图文步骤，修正新版代码、Secret、DNS 和权限说明。**38 张插图均已保存到本地并进行隐私遮盖，不依赖原金山文档链接。**

> 本教程阅读可离线，注册账号、操作控制台和真实部署仍需联网。截图可能是旧控制台，仅用于定位菜单；具体字段以正文为准。域名、Worker 名称、数据库与密钥都请换成自己的，不复制截图里的实际账号／域名。已有部署请先看 [升级指南](UPGRADE.md)。

## 一、准备工作

1. 一个 [Cloudflare 账号](https://dash.cloudflare.com)。
2. 一个你有权控制 DNS／名称服务器的域名。已有域名可跳到第三节。
3. 最新个人版单文件 [personal/worker.js](../personal/worker.js)。在 GitHub 文件页点击 **Raw**，复制完整内容，而不是只复制 `src/personal.js` 中的几行 import。
4. 两个分别生成并妥善保管的随机值：认证根 `ADMIN_TOKEN`；若需要网页 TG，再准备 `SETTINGS_ENCRYPTION_KEY`。不要使用教程示例密码。

普通登记线路不需要 VPS；只有选择 VPS 中继时才需要自备 VPS、域名和可信 TLS 证书。Cloudflare / D1 / 域名商都有配额与条款，免费套餐不是无限视频服务。

## 七、添加域名：优选接入保持灰云

下面统一以 `proxy.example.com` 为个人版入口。

**按作者教程添加优选 IP／优选域名时，DNS 记录要保持灰云（DNS only）**。域名／Route 用来匹配入口，优选记录用来选择接入地址，不能把“添加了 Route”当作灰云优选链路已自动配置好。

先按下方 Route 表单核对入口，再到第十节添加相同记录名的灰云优选 A／AAAA／CNAME。已有可用接入不改代理状态，完成后必须用实际入口 `/health` 验证 Worker 和版本。

### 不使用优选时的另一选择：自定义域

Worker → 设置 → 域和路由 → 添加 → **自定义域**，输入 `proxy.example.com`。按提示由 Cloudflare 建立 DNS 与证书；若同名记录冲突，先核实它是否属于其他服务，不能直接删。

此方式不要额外把记录改为灰云／优选 CNAME，也不要把 VPS `relay` 记录混作主入口。

### Worker Route 表单位置

Worker 的域和路由页面也可添加 Route。

![域和路由设置入口](assets/deploy/step-30.webp)

选择 `example.com` 区域，填写 **`proxy.example.com/*`**，确认指向个人版 Worker。

![Route 表单位置示意，模式以正文为准](assets/deploy/step-31.webp)

图中旧通配模式不能直接照抄；个人版不必接管所有 `*.example.com`。DNS 设置见第十节，**填优选地址的记录保持灰云，不因本节表单改成橙云**。

补充区分：Cloudflare 官方普通橙云 Route 方案要求其 DNS 被代理；它不是本文灰云优选接入的同一种方案。优选地址仍须支持正确的 Host／TLS／Worker 承接；未命中时核查实际绑定和接入条件，不能以改橙云冒充完成优选。

## 八、设置环境变量与 Secret

Worker → 设置 → 变量和机密。**不要把真实密钥写入 Markdown、GitHub 或截图，也不建议以普通聊天／微信笔记保存。**

| 名称 | 类型 | 示例／说明 |
| --- | --- | --- |
| `ADMIN_TOKEN` | Secret | 自己生成的强随机认证根；首次后台登录使用 |
| `BASE_DOMAIN` | 文本 | `example.com` |
| `DNS_RECORD_NAME` | 文本 | `proxy`，与入口 `proxy.example.com` 对应 |
| `SETTINGS_ENCRYPTION_KEY` | Secret | 32 随机字节的 Base64；网页 TG 保存时需要 |
| `CF_API_TOKEN` | Secret，可选 | DNS／CF 统计需要时添加，权限见下一节 |
| `DISABLE_DIRECT_PROXY` | 文本 | `1`，默认关闭公共原始 URL 转发 |

可信终端中分别运行：

```bash
openssl rand -hex 32
openssl rand -base64 32
```

前者作为一份认证随机根，后者作为另一份通知加密密钥，不要混用输出。个人版不能用多人版的 SESSION_SECRET 派生方案代替通知专用主密钥。

还可设置 `CF_ZONE_ID` / `CF_ACCOUNT_ID`，以及兼容通知变量 `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID`；推荐在网页中单独配置和测试 TG。所有变量设置后确认部署生效。

## 九、API Token 的正确权限

代理线路本身不依赖 Cloudflare DNS API；只有后台 DNS 和 CF 统计等功能需要运行 Token。

| 权限 | 用途 |
| --- | --- |
| Zone → Zone → Read | 识别 Zone／账户 |
| Zone → DNS → Edit | 创建、替换 DNS 记录 |
| Zone → Analytics → Read | Zone 范围流量统计／日报 |
| Account → Account Analytics → Read（按需） | 账户／Worker 范围统计 |

作者原稿权限表的用途有错位，以上表为准。仅授权自己的目标 Zone；**运行 Token 不必有 Workers Scripts → Edit**，不要给它整账户管理员权限。

![创建 API Token 页面](assets/deploy/step-32.webp)

新版权限名称和截图可能不同，按上表选择，不要一键全选全部权限。

![权限分类位置示意](assets/deploy/step-33.webp)

![继续查看摘要](assets/deploy/step-34.webp)

核对资源范围与权限，再创建。

![Token 权限摘要](assets/deploy/step-35.webp)

只通过可信通道保存 Token，并把它作为 Worker 的 `CF_API_TOKEN` Secret。创建页面的验证命令也会包含 Token，发截图时 **输入框和命令都要遮盖**。

![Token 创建完成，凭据区域已完全遮盖](assets/deploy/step-36.webp)

如果曾把真实 Token 发到公开文档，应先吊销重建；把截图后补打码不能收回已经公开的旧值。

## 十、核对 DNS

回到你自己的域名 → DNS → 记录。

![域名列表入口](assets/deploy/step-37.webp)

![DNS 记录管理入口](assets/deploy/step-38.webp)

- 使用 **优选 IP／优选域名**：类型 A／AAAA／CNAME 对应优选 IPv4／IPv6／域名，名称为 `proxy`，目标填你选择的地址，**关闭代理，保持灰云（DNS only）**。不要指向源站真实地址或把记录改为橙云。
- 作者原稿示例为 `youxuan.cf.090227.xyz`；这是第三方优选目标示例，不保证一直有效，应按实际可用性选择并验证自己的入口。
- 选择 **不使用优选的自定义域**：保留 Cloudflare 自动管理的记录和证书，不与手工灰云优选记录混用。
- 只有明确改用 **普通橙云 Workers Route** 时才按其规则配置橙云 DNS；这不属于“添加优选记录”的操作。
- VPS 的 `relay.example.com` 是另一个服务，通常直达 VPS，使用与它匹配的 TLS 证书；不要混淆它与 Worker 主入口的代理状态。
- 第三方优选服务不是本项目保证。不要把已有网站／邮件记录改成教程示例；灰云优选、普通橙云和 Worker 自定义域三者要分开看。

## 十一、访问与配置线路

1. 访问 `https://proxy.example.com/health`，返回 200 且 `version` 为 **`v6.4.9-refactor.8`**。若是旧版本，检查域名是否绑定另一个 Worker。
2. 打开 `https://proxy.example.com/admin`，用最初设置的 `ADMIN_TOKEN` 登录。
3. 在设置 → 安全中验证当前密码，再设置两次 12–128 字符新密码。改密后旧会话退出；原 `ADMIN_TOKEN` 仍是认证根，不能删，且不再是第二个登录密码。
4. 新建线路：前缀 `demo`；目标填写你有访问授权的服务基址，如 `https://media.example.net`。多目标按行填写；不要把目标填成 `/System/Info/Public` 或具体影片地址。
5. 客户端服务器地址填 **`https://proxy.example.com/demo`**，再按上游账号登录。任意 `/http://源站/...` 默认关闭，不要为了方便开放公共代理。
6. 实际测试起播、拖动、长播、字幕和 Range。公共信息接口 200、海报正常、健康测试通过，都不能替代真实媒体验收。

## 十二、网页 TG 与 Cron

1. 确认已设置独立 `SETTINGS_ENCRYPTION_KEY` Secret。
2. 后台设置 → 通知：输入自己的 Bot Token 和数字 Chat ID，保存后再测试；Token 留空保持，明确清除后停用，不回退旧机器人。
3. 按需要打开健康检查、线路告警与日报。通知只使用安全备注／匿名编号，不主动发送源站地址或原始错误；不要把秘密写进备注。
4. Cloudflare → 触发器 → Cron，可添加示例 **`*/10 * * * *`**。Cron 使用 UTC，日报在北京时间 23 点判断，必须覆盖 UTC 15 点。已有服务升级保持原 Cron，不按教程重写。

Bot 仅发送通知，不增加入站管理命令，不接管你原来的 webhook。密钥轮换与恢复见 [通知与密码安全](WEB-NOTIFICATIONS-SECURITY.md)。

## 十三、可选 VPS 中继

先看 [中继安装与源码](../relay/README.md)，不要执行老版本预编译一键脚本覆盖已有服务。

- 自动：优先 Worker；满足安全条件才尝试 VPS，成功后实例内短期优先 VPS。
- 开：强制 VPS，缺配置明确报错。
- 关：不经过 VPS。

旧 `image` 按自动兼容。全局未配置地址／密钥或关闭时，自动模式不会调用 VPS；成功的视频流不会因为“下载慢”中途重发。详细状态、POST 边界与恢复探测见 [自动回退说明](AUTO-RELAY-FAILOVER.md)。

## 十四、更新、备份与故障定位

- 更新前保存旧 Worker 版本、完整 D1、绑定／Secrets、域名、Cron、智能放置和中继配置。网页配置导出 **不是完整数据库备份**。
- 日常只替换正确发行版代码，保留原 DB、密码、线路和配置。代码回滚不自动恢复数据，旧版本可能不理解新密码／会话／加密通知。
- 播放转圈时记录播放器、时区、复现时刻，抓取同次播放的 PlaybackInfo、媒体 GET／Range 和跳转。不要只提交服务器信息接口日志，也不要公开 Token／Cookie／签名 URL。
- 完整变量与故障表：[部署总指南](../DEPLOY.md)；升级前逐项检查：[UPGRADE.md](UPGRADE.md)。
