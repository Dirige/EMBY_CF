# 网页通知与登录密码设置

> **最新状态（2026-11-24）**：个人版已发布 `v6.4.9-refactor.8`；多人版同步独立通知和按账号改密后已发布 `v6.8.11-multi-refactor.3`，见 `MULTI-SYNC-CHECKLIST.md`。两版发布状态分别以 `PERSONAL-PUBLIC-ACCEPTANCE.md` 和 `MULTI-PUBLIC-ACCEPTANCE.md` 为准。Bot 只保留通知，不增加入站管理或接管既有 webhook。

以下主体是个人版安全设计及 2026-11-21 的历史实现／发布前记录；多人版不直接套用个人版的认证表、pepper 或密钥，差异见下节。

## 多人版安全差异（2026-11-24）

- 通知仅管理员可设置；TG Token 与 Chat ID 使用独立 `multi_private` AES-GCM 密文，不进入普通 settings／导出。支持独立 `SETTINGS_ENCRYPTION_KEY`，或从原 `SESSION_SECRET`（至少 32 字节）做固定用途 HKDF 派生；不从 `ADMIN_TOKEN` 派生 TG 主密钥。
- 原环境变量整组兼容，网页保存后整组优先；Token 留空保持，明确清除后禁用，密文损坏时拒绝回退。添加专用密钥不会立即丢失旧的 session 派生密文，下一次保存才迁移到专用密钥；轮换实际使用的根仍需重新保存或安全迁移。
- 内置管理员使用 `multi_private.admin_password` 私有记录；普通用户和数据库管理员保留原用户表／PBKDF2，改密只撤销当前账号。触发器轮换 `user_epoch:<id>`，跨实例认证直接读取最新状态；未改密旧账号及旧 Cookie 保持兼容。
- 登录的密码校验和会话签发来自同一数据库凭据／epoch 快照，避免旧密码缓存配上新签名根。普通用户条件改密使用 `UPDATE ... RETURNING id`，不把触发器写入计数误当并发冲突。
- 新密码须 12–128 字符，必须验证当前密码并使用同源 JSON；字段不回显、不导出、不记录。内置管理员改密后初始管理密钥不是第二个登录密码；其他用户不会被一起退出。
- 管理员恢复只能在可信 Cloudflare 通道中备份并操作多人版私有记录／会话根，不能照抄下方个人版 `admin_private` SQL，也不能改用个人版 D1。轮换多人版 `SESSION_SECRET` 会影响全部用户会话及 session 派生 TG 密文，必须先评估并安全迁移通知；日常网页改密不轮换该绑定。

## 设置 → 通知

- 网页可填写 Bot Token 和数字 Chat ID，单独保存、测试或清除停用。
- 首次无网页配置时兼容 `TELEGRAM_*` / `TG_*` 环境变量；网页配置整组优先，避免混用机器人与会话。
- Token 留空保持已有值；明确清除后禁用 TG，不回退到环境变量。Webhook 独立，不受清除 TG 影响。
- Token 与 Chat ID 整组使用 AES-256-GCM 加密存入独立 `admin_private` 表；每次保存使用随机 nonce 和固定用途 AAD。
- 主密钥 `SETTINGS_ENCRYPTION_KEY` 必须是 **32 个随机字节的 Base64 编码**，仅配置为 Worker Secret。不通过网页设置，也不写入源码、普通 settings 或导出。
- 主密钥不存在时仍可使用旧环境变量通知，但无法网页保存。主密钥错误或密文损坏时停止使用该 TG 配置，不回退旧机器人。
- 轮换主密钥需安全迁移已有密文，或在新密钥生效后重新输入 Token 与 Chat ID。不要直接换密钥后期待旧配置可解密。
- 日报开关、线路告警开关独立保存；健康检查关闭时不会运行定时探测。日报时间固定北京时间 23 点，仍需 Cloudflare Cron 覆盖该时间。
- 保存最近一次测试／日报／健康告警发送时间及整体成功状态（TG 或 Webhook 任一成功）；不保存原始响应或秘密。

## 线路保密

- 异常与恢复消息优先使用安全的线路备注、节点序号和状态；备注为空或未通过安全检查时使用 `R-XXXXXXXXXXXX` 匿名编号。
- 备注必须是可公开的简短服名（最多 64 个 Unicode 字符）。使用保守字符白名单，含地址／路径／实体编码标点、凭据关键词或疑似长 Token 的整条备注不发送，不尝试从混合内容中猜测公开片段；同时排除已知环境密钥和目标 URL 中的凭据／查询值。正常备注转为纯文本并转义 Telegram HTML。
- 不自动发送源站 URL、入口域名、路由前缀、签名参数或探测原始错误。不要把秘密或编码后的秘密当作服名；自动检查不能判断任意短字符串是否是未标注的秘密。
- 编号由管理员根密钥对线路前缀做 HMAC 得到，不直接用可枚举的前缀哈希。根密钥变化或前缀更名会改变编号；节点序号按当前目标列表顺序编号。
- 管理员线路卡片保留相同编号，便于定位回退告警。地址与诊断细节仅在鉴权后台查看。
- TG 与 Webhook 使用同样的无地址消息；日报也移除入口域名和原始统计错误。禁用链接预览并不能防止地址泄露，因此不是保密措施。
- 大批量告警仅在完整消息之间分组，每组不超过 Telegram 的 4096 字符限制，不截断备注或 HTML 实体。
- 本轮不修改其他独立部署的 Worker；旧线上版本在新版部署前仍可能发送旧格式通知。

### Telegram Bot 管理边界（设计参考，本轮已取消）

用户明确选择只做通知，不做 Bot 管理；现有 Bot 另有用途。本轮未新增 webhook 或入站管理代码，不开启 Bot 写权限，不替换既有消息接收程序。以下内容仅为可行性与安全边界参考，并非实现计划或操作授权。

- 可以增加路线列表、添加／编辑／停用路线和替换 DNS 记录；应复用现有校验、缓存失效和脱敏审计，不提供任意 SQL 或 Cloudflare API 操作。
- 写入前必须通过网页绑定明确的 Telegram 用户 ID，仅接受该管理员的私聊。通知 Chat ID 可能是群组，不能直接当作写入管理员授权。
- 路由或 DNS 修改采用预览、二次确认、短期有效的操作标识和幂等处理；DNS 权限限制在配置区域与明确选定的记录。
- 不覆盖未确认归属的现有 Bot webhook；新增接入需先只读核查，使用独立 webhook Secret 验证 Telegram 请求。配置应从网页保存，不要求增加日常手填 Worker 变量。
- 通过 Bot 输入目标地址会把地址提交到 Telegram 的普通云端聊天，不能称为端到端保密。用户需先选择允许私聊输入，或只通过网页填写敏感字段、Bot 负责安全选项与确认；未作决定前不启用入站写功能。

## 设置 → 安全

- 必须验证当前密码，两次输入 12–128 字符的新密码；保留密码首尾空格，登录页面不裁剪网页密码。
- 数据库只存随机盐、PBKDF2-SHA256 派生结果、算法版本和随机会话 epoch，不存明文密码。
- PBKDF2 为 Workers Web Crypto 支持的 100000 次；派生输入先用 Worker Secret `ADMIN_TOKEN` 做 HMAC pepper。数据库单独泄露不足以离线验证密码。`ADMIN_TOKEN` 不得与数据库共同导出或存储。
- 网页设置密码后原 `ADMIN_TOKEN` 不再作为第二个登录密码，但仍作为 pepper 和会话签名根密钥，不能删除或随意轮换。
- 改密采用条件写入，防止并发覆盖；每次检查会话读取最新密码状态，不做认证状态跨请求缓存。修改成功后所有旧会话失效，当前浏览器清除 Cookie。
- 登录和改密共用既有失败限流（单 isolate / IP，5 次、10 分钟）；这不是跨节点全局防爆破，生产仍应保留 Cloudflare 限流与安全策略。
- 新增写入接口要求同源 Origin 和 JSON 请求；敏感字段不回显、不记日志、不导出，也不能从配置导入覆写。
- 密码记录损坏或数据库不可用时拒绝认证，不静默恢复旧密码。

### 忘记密码：Cloudflare 管理员恢复

1. 仅在可信 Cloudflare 管理通道操作，暂停后台操作并备份数据库（备份含秘密，需安全保存）。
2. 将 Worker Secret `ADMIN_TOKEN` 轮换为新的强随机根密钥并确认部署生效，以废止所有原始根密钥会话。不要改动通知加密主密钥。
3. 在该个人版的独立 D1 执行 `DELETE FROM admin_private WHERE key = 'password'`，仅删除密码记录，不删除 TG 配置。
4. 用新 `ADMIN_TOKEN` 登录，再在网页设置新的登录密码。确认旧密码及旧会话均不可用。
